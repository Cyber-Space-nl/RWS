# RWS v0.1.0-beta.7

**Experimental prerelease.** The standalone download targets Linux x86-64 with GNU libc and
is built on Ubuntu 22.04. Linux 5.6 or newer is required for contained file opening. This release
does not establish production readiness, independent security review or compatibility outside
the tested environments.

## What's new

- With TLS configured, HTTP automatically redirects to HTTPS with status 308, preserving the
  path, query and method. `server.redirect_http_to_https = false` disables this behavior.
  Without TLS, HTTP is unchanged. Redirects use the configured site host and HTTPS listener port.
- Static-only ACME HTTP-01 GET/HEAD challenges remain available over HTTP for certificate renewal.
- `[[sites.locations]]` mounts a static/PHP application under a URL prefix with its own public
  root, index, PHP-FPM pool, optional front controller/gzip and static-cache namespace.
- Locations support optional bcrypt htpasswd Basic Auth, mount-relative path/file deny rules
  and noindex headers. Hidden components and denied symlink targets are blocked; protected cache
  hits still require authentication. Authentication requires HTTPS and uses bounded workers.
- PHP receives the mount prefix in script URLs, the original request URI/query and the real
  listener's HTTPS state/port. The outer Basic Auth header is removed before PHP dispatch;
  `REMOTE_USER` and `AUTH_TYPE` identify the authenticated user.

## Live use and validation boundaries

[insaider.nl](https://insaider.nl/) runs on RWS with native HTTPS, PHP-FPM, automatic redirects
and protected phpMyAdmin under `/database/`. The preceding source build was exercised with the
real PHP 8.5-FPM pool: phpMyAdmin's login page and assets loaded, while internal files and
directories remained blocked. The existing password file was preserved. No SQL login or database
mutation was performed by that validation. Certificate-renewal dry-runs succeeded.

The source suite has 76 workspace tests, including mount/auth/cache boundaries, encoded paths,
symlink denial, FastCGI metadata and an actual TLS process. These checks and the live source-build
test are distinct from testing the downloadable archive. Download checksums and build identity
are provided with the archive; release publication also requires artifact smoke checks.

## Configuration and installation

See [README.md](../../README.md#applications-under-a-url-prefix) and `config.example.toml`.
Location URL prefixes and public roots must not overlap. Directory listing is disabled on
mounts. Basic Auth accepts bcrypt `$2a$`, `$2b$` and `$2y$` hashes, cost 4–16, and passwords up to
72 bytes. Use `htpasswd -B`, store the file outside public roots, grant RWS read access and
restart after changes. Other htpasswd formats are rejected. An unreadable or invalid authfile
fails startup/`--check`.

The archive contains `rws`, `rws-ws-load`, `rws-bench`, configuration, documentation and dependency
license material. Systemd installers, units and helpers are in the matching source tree, not the
standalone archive. For source installation, see [UBUNTU_INSTALL.md](../../UBUNTU_INSTALL.md).

```bash
sha256sum -c SHA256SUMS
tar -xzf rws-v0.1.0-beta.7-x86_64-unknown-linux-gnu.tar.gz
cd rws-v0.1.0-beta.7-x86_64-unknown-linux-gnu
sha256sum -c BINARY_SHA256SUMS
bin/rws --version
```

Back up existing installations and test rollback before upgrading. Trusted public roots and
isolated PHP-FPM pools remain required. HTTP/2, slow clients and sustained overload need further
validation. The proxy buffers per-request data and does not proxy WebSocket upgrades or generate
trusted forwarding headers. Independent external review and human review of distribution
obligations remain outstanding.

## Build

On x86-64 Ubuntu 22.04 with binutils, Python supporting tarfile's `data` filter and Rust 1.88+:

```bash
python3 tools/release/assemble.py --output /tmp/rws-beta-7
cd /tmp/rws-beta-7
sha256sum -c SHA256SUMS
```

Commit source changes and unset build override variables first. The builder rejects binaries
referencing glibc symbols newer than 2.35. This check does not by itself guarantee compatibility;
builds are not claimed to be byte-for-byte reproducible across environments.
